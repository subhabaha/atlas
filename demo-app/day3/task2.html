Retrieval Strategy Benchmark

Dense retrieval fails on part numbers. Sparse fails on paraphrase. Averaged over a mixed question set the two look identical — and neither failure is visible in the answer. One corpus, one gold set, five strategies, one table built to be shown to management with numbers on it.

The scenario

The corpus is Corpus B — 300 synthetic markdown service bulletins for an industrial air-compressor organisation (product families GA-30, GA-75, ZR-160), each with YAML front-matter: doc_id, doc_type, product_family, revision, status, access_level. Retrieval quality is only measurable when you know which passage is correct — so this corpus ships with a scoreboard the real manuals cannot give you.

The gold set is 60 questions, class-labelled, because a mixed set is what exposes the difference between strategies. Report every metric per class as well as overall.

Reciprocal Rank Fusion — the whole of it
Dense and sparse scores are not on comparable scales, so RRF ignores the scores entirely and uses only the ranks. It needs no tuning, which is most of why it is the default.

score(d)  =  Σlists   1 / ( k + rank(d) )

k = 60 by convention. A document ranked #1 in one list and #40 in the other still fuses ahead of one ranked #5 in both — rank presence beats single-list dominance.

Metadata filter — the wrong-variant case
A GA-30 question, with a near-identical GA-75 procedure in the corpus.

Why it is underused. It requires metadata captured at ingestion — Task 1’s level 4. Teams reach for a better embedding model instead, because that is a change they can make without revisiting the pipeline. Frequently the largest single improvement available, and almost always deferred.

No-answer detection — the ten out-of-corpus questions
Without detection, retrieval always returns its top matches however weak, the model answers anyway, and the user receives a fluent, confident, wrong answer — cited to a document that does not support it.
Before declined 0 / 10
After declined 9 / 10

Implemented as two things together: a threshold on the reranker score, and an explicit instruction that the model answer only from the provided passages and say so when they are insufficient. Declining to answer is a feature, not a failure.

The trap the average hides

Dense retrieval fails silently on identifiers

Ask for the torque on HX-4471-B and a pure-embedding index returns a plausible passage about a different part — because the identifier fragmented into meaningless sub-word tokens (Task 1) and the vector landed near semantically-similar neighbours. Answer-correct on identifier questions: 0.42. Nothing in the answer signals the miss.

One average, two cancelling failures

Dense overall 0.71, sparse overall 0.68 — nearly identical, and a report that stops there recommends a coin flip. The class breakdown shows dense at 0.90 on conceptual / 0.42 on identifier, sparse the mirror image. Report per class, or you learn nothing.

A confident answer is not a grounded one

Before no-answer detection the system declined 0 of 10 unanswerable questions and cited a document for each. A citation to a document that does not support the claim is worse than no citation — the user checks, sees a reference, and trusts it.

The lesson this build makes undeniable

Measure retrieval and generation separately, or you cannot tell which one failed.

Context recall is a retrieval number computed with no model at all; faithfulness is a generation number. When they disagree, the diagnosis is immediate. Most retrieval failures are retrieval failures — not model failures, not prompt failures — and the fix is almost never a bigger embedding model.

Defend your result

“On identifier questions dense scored 0.42 and sparse 0.90; hybrid scored 0.86. Reranking added 220 ms and 25 points of precision while cutting tokens by 41%. Our system declined correctly on 0 of 10 out-of-corpus questions before we added detection, and 9 of 10 afterwards.”
