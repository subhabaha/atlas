Fix a Weak Pipeline, and Watch It

Retrieve twenty, rerank, pass four: cheaper, faster and more accurate from one change. Start from a deliberately weak pipeline, apply five improvements one at a time, and measure the stages separately — so the ablation tells you not only that the system improved, but which change earned which part of the improvement, and which earned nothing.

The scenario

The baseline is built badly on purpose: fixed 512-token chunking with no overlap, dense retrieval only, no reranking, no metadata filtering, top-20 passages, and a prompt that does not constrain the model to the passages. You already know from Tasks 1 and 2 that this performs poorly — build it anyway, because every delta is measured from it.

Then instrument before improving. Eight metrics: four computable without a model because you have a gold set, four that need the model as a judge. Knowing which is which is what makes the numbers trustworthy.

What the attendees must build

  • Eight metrics, the four model-free clearly separated from the four model-judged
  • Traces with eight spans per request, including context assembly with per-passage token counts
  • An ablation table — one change at a time, deltas on every metric plus latency and cost
  • At least one change reported as no-help or negative, with its number
  • Citations validated programmatically, not merely produced
  • An eight-panel observability dashboard, each panel carrying its alert condition
  • A regression suite seeded with the four failures found earlier today
  • The cumulative context-recall gain traced from baseline to final

Three improvements from one change

Step 3 raised quality (recall +0.06, citation +0.22), and cut latency 3.0 s → 1.7 s, and halved cost — because reranking let us pass 5 passages instead of 20. Three wins from one change is rare; note it explicitly.

The honest negative

Metadata filtering measured −0.005 on recall here — this pipeline’s metadata was thin, so the filter removed the occasional right answer for no gain. We removed it: simpler, cheaper, faster at no measurable cost. (On Task 2’s richer metadata it was the winner — measure, don’t assume.)

The observability dashboard — eight panels, each with an alert
Tokens per request is a quality signal, not just a cost signal: a sudden rise usually means retrieval quality dropped and the system pulled in more passages to compensate. It is one of the earliest warnings available, and needs no labelled data.

The habits this build breaks

Changing four things at once

If you change chunking, retrieval, reranking and the prompt together and performance improves, you have learned almost nothing — you do not know which one to keep and which is adding complexity for free. One change at a time, or the ablation is not an ablation.

Unvalidated citations

Citation enforcement is not producing a reference — it is validating programmatically that the cited passage was actually retrieved and does contain the claim. Unvalidated citations are frequently plausible and wrong, which is worse than no citation: the user checks, sees a reference, and trusts it.

A quality number with no cost beside it

Automatic deduction in this bootcamp: minus ten for any answer-quality number reported without its cost. Every row of the ablation carries p95 and €/query for exactly this reason.

The lesson this build makes undeniable

Retrieve broadly, rerank precisely, pass few.

Cheaper, faster and more accurate from one change. And the ablation is what lets you say so with a number — it tells you which change earned which part of the improvement, and which earned nothing and should be removed. An engineer who can check the source will trust a system that is right 85% of the time; one who cannot will abandon a system that is right 95% of the time.

Defend your result

“Baseline context recall was 0.58; after all five changes it is 0.88. The largest single contribution came from section-aware chunking (+0.13). Metadata filtering contributed nothing measurable (−0.005) and we removed it. Cutting from 20 passages to 5 changed quality by +0.06 and cost by −49%.”
