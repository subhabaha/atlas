The Feedback Loop, With Arithmetic

Labelling the cases the model finds hard beats labelling at random by a wide margin — but only if confidence is calibrated. Build the loop, prove with a measurement that it is worth building, and prove with arithmetic that it can actually run.

The scenario

From a low-confidence prediction to a retrained, validated, deployed model. Uncertainty sampling selects the cases the model is least sure about — and that only works if the model's confidence means something. Most neural networks are over-confident, so the loop must fix calibration before it trusts a single confidence score.

Then two questions get answered with numbers: is active learning worth it (a learning-curve experiment), and can the review workload it creates actually run (the volume arithmetic)?

The apprentice the analogy that makes it obvious

You would not train an apprentice by having them repeat the tasks they already do correctly. You would put them on the jobs they find difficult, with someone watching. Active learning is that principle applied to a training set — every uncertainty-selected label lands where the decision boundary is unclear, while random labelling spends most of its budget on easy cases the model already handles.

What the attendees must build

  • Calibration measured before relying on confidence — reliability curve and ECE before & after Platt scaling
  • Random vs uncertainty learning curves, accuracy against labels bought, from a 200-image seed to 1,200
  • The label saving read off as the horizontal distance between the curves at a stated target accuracy
  • A routing rule + volume arithmetic on the diagram: parts, deferral, reviews/shift, seconds/review, capacity
  • A capture schema written to on every review — including guideline version and reviewer attribution
  • The train-or-evaluate split assigned at capture time, demonstrably never both — Day 1's leakage rule, operational
  • Reviewer feedback closed visibly, as a named element with an owner — not an aspiration
  • The limit named: active learning targets epistemic uncertainty; your Task 1 kappa says how much of it is reducible

Why it comes first

Before scaling, when the model says 0.90 it is right about 76% of the time — so "least confident" does not mean what uncertainty sampling assumes, and the loop selects poorly. Platt scaling on a held-out slice pulls the curve onto the diagonal (ECE 0.14 → 0.03). It is the difference between an active-learning loop that pays and one that quietly does not.

The limit: active learning reduces epistemic uncertainty — the kind more data fixes. Where the task is genuinely ambiguous (aleatoric), labelling adds contradictory examples. Your Task 1 κ 0.78 is how you know which is which, and therefore whether the loop will pay at all.

The routing rule doubles as the label source

The parts in the uncertain band are exactly the high-information cases uncertainty sampling wants — so the review loop and the active-learning experiment are the same pipeline. Widen the band to 6% and reviews rise to 3,456, above the 2,880 capacity; the routing threshold that produces it is not available until you add a reviewer or divert the part. Choose the band the capacity can clear, then let those reviews become next month's training labels.

And a protected set the loop never touches

A separate held-out set is scored on a fixed schedule and refreshed from production only deliberately, with an expert verifying every added case. New cases flowing into both training and evaluation quietly inflate every future measurement — write the split once, at capture, and record it in the schema.

Close the loop visibly — a named element with an owner
The point that decides whether the loop still runs in six months. Correction rates decay within weeks if reviewers cannot see that their work mattered. This is a human factor, and it is more decisive than any technical choice in the loop.
Named element

Reviewer Impact Digest

Weekly note back to each reviewer: which of your corrections entered training, how much they moved recall, and on which slice.

Owner

Quality Lead · m.okonkwo

Named, not "the team". Accountable for the digest going out every week and for reconciling disagreements before they reach training.

Failure mode it prevents

Silent decay

Without visible impact, correction rates fall and the label supply that feeds the loop dries up — the loop stops compounding and nobody notices for a quarter.

The trap that makes the loop quietly stop paying

Uncertainty sampling on an un-calibrated model

If confidence is not calibrated, "least confident" points to the wrong examples, and the loop under-performs for a reason nobody diagnoses — it just looks like active learning "did not help here". Calibrate first (ECE 0.14 → 0.03, two lines), then select. Skipping this is the single most common way the loop is built and quietly wasted.

New cases flowing into both training and evaluation

Retrain on freshly reviewed data without a split assigned at capture time and the same corrected case can land in both sets — inflating every future measurement. This is Day 1's leakage lesson in operational form. Write the train-or-evaluate split when the review is captured, not when the model is trained.

A correction that costs four clicks

If correcting a label takes four clicks and accepting the model takes one, reviewers accept — and the most valuable data the system produces is never captured. Build the interface so the correction is the default path; the data quality is set by the UX, not the model.

The lesson this build makes undeniable

A feedback loop only compounds if calibration, capture and validation are all present — most have none of the three.

Active learning is worth a measured, budgeted amount — hundreds of labels you never have to buy — but only on a calibrated model, only where the uncertainty is the reducible kind, and only if the reviews it generates fit capacity and are captured in a form that reaches training without leaking into evaluation. Close it visibly, with an owner, or it decays within weeks.

Defend your result

"Calibration error was 0.14 and is now 0.03. To reach 0.87 accuracy, random sampling needed ≈ 850 labels and uncertainty sampling needed ≈ 470 — a saving of ≈ 380 labels per refresh. At our routing threshold that is 2,304 reviews per shift against a capacity of 2,880. Our loop stores the corrected label, the model's proposal and confidence, the reviewer and guideline version — and new cases go to training or evaluation but never both, because the split is written at capture time."
