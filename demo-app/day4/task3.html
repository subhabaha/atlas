The MLOps Pipeline, Built

A gate that has never rejected anything is not a gate — it is a logging statement. And rollback time is a number or it is a hope. MLOps is not a toolchain; it is five questions made answerable, and this bench answers them with a model that actually gets blocked.

The scenario

Do not start with the tooling; start with the unanswered question. Buying a platform to solve a discipline problem is how organisations end up with an expensive platform and the same problem. Five questions, and if the honest answer to any is no, that is your priority.

The questionWhat answers it
Can you reproduce a result?Four versions bound to every run
Can you roll back?A registry + a stopwatch-timed rollback
Can you tell it degraded?Monitoring — three signals need no labels
Can you ship a change safely?A gate that rejects something today
Can you retrain reliably?Triggers with a threshold and a duration

The binding — four versions on every run manifest.json (auto-written)

"dataset": "crack-40k" @ "a1f4c9e",
"features": "mnetv3-penult" @ "7d2be08",
"model": "logreg-C0.5" @ "v2.4",
"label_guide": "guideline" @ "g3-boundary",
"trained_by": "m.okonkwo",
"hypothesis": "relabel raises recall ≥0.06"

Roll back the model without rolling back the feature code and you get a model running on inputs it was never trained for — often worse than either version alone. The binding is the point; a run missing any of the four fails.

What the attendees must build

  • Four versions — dataset, feature, model, label-guideline — bound and auto-recorded on every run, a missing one failing
  • The seven-stage pipeline: commit · validate · train · evaluate · gate · register · deploy
  • An evaluation gate with criteria set before the run, that actually rejects a deliberately worse model today
  • A registry recording lineage, per-class + per-slice metrics, approver and known limitations
  • A rollback timed with a stopwatch, from cold start, by someone who did not build the pipeline
  • Shadow deployment running, with a disagreement rate reported and localised
  • The input-distribution monitor firing on the shifted group before any labelled accuracy figure could exist
  • Retraining triggers each written with a threshold and a duration, not a threshold alone

The trap that ships bad models quietly

A gate that has never rejected anything

If your gate has approved every model it ever saw, you have a logging statement, not a gate — and you will not know which one you built until the day it matters. The fastest way to find out is to train a deliberately worse model (label noise left uncorrected) and push it. Select v2.5 above: it is blocked on the primary metric and calibration, and it is not argued into production. That is what stops quality drifting downward one small exception at a time.

Rolling back the model but not the feature code

A model rolled back without its feature version runs on inputs it was never trained for, and frequently performs worse than either version alone. Teams discover this during an incident. Bind all four versions on every run so a rollback restores the whole lineage, not just the weights.

"We would have to check with the person who set it up"

That is the same answer as "we do not know our rollback time." Time it with a stopwatch, cold, with someone who did not build the pipeline. Ours is 47 seconds. A number you can defend beats a capability you assume.

The lesson this build makes undeniable

The evaluation gate is what makes MLOps real — and it only exists if it has rejected something.

Reproducibility is four versions bound together. Recoverability is a rollback measured in seconds by a stranger to the code. Observability is a signal that fires before the labels that would confirm it can exist. None of these is a platform you buy; each is a discipline you demonstrate — with a model that gets blocked, a stopwatch that gets read, and a monitor that fires six days early.

Defend your result

"Our gate rejected a model that scored 0.905 because it did not beat production 0.912 and its calibration error was 0.071 against a 0.05 bar. Rollback took 47 seconds, done by someone who had not seen the pipeline. Shadow shows the two models disagreeing on 3.8% of parts, concentrated in low-light. Our earliest degradation signal is input-distribution drift, and it fires six days before any labelled accuracy figure could."
