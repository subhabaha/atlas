The Field-Service Agent System

Autonomy multiplies error rather than adding it. A step that is 90% reliable is 90% over one step, 73% over three, and 43% over eight. Everything on this page — the contracts, the per-step spans, the gates — is a response to that one table. The largest reliability gain comes from making the system less agentic.

The scenario

An engineer is stood at a machine. The system must interpret the symptoms, find the right procedure for that revision, check what has been done before, propose an action, reserve the parts and file the report. Six responsibilities — and exactly one of them takes an irreversible action.

The runtime is ~150 lines you wrote yourself: a loop with a step budget, a cost budget, structured state, and a span emitted per step. No framework — you need to see every step boundary, because the step boundaries are the lesson.

What the attendees must build

  • All five budgets set in code before the first run, with the abort path tested
  • Six agents, each with its tools, authorisation boundary, and what it may not do
  • Two full contracts — including the context boundary and what is deliberately withheld
  • A per-step success table across 40 scenarios: attempted · succeeded · retried · escalated · tokens · latency
  • Predicted end-to-end (product of per-step rates) versus the observed end-to-end
  • Two deterministic steps converted to plain code, with the before-and-after on success, cost and latency
  • An approval gate on the spare-parts action, gated on irreversibility — not confidence
  • The gate timed with an outside approver who never saw the code

Watch for: a gate that makes the approver reconstruct the agent's reasoning from logs provides the appearance of control and none of the substance — worse than no gate, because everyone believes it works.

The trap Copilot will hand you

A sub-agent that is a tool with extra steps

Copilot will happily turn every responsibility into an autonomous peer that calls a model. Most of them are lookups, calculations, format conversions and threshold comparisons — code, not judgement. Every one you leave as a model call is a step that can fail probabilistically, and because the chain multiplies, it drags the whole run down. Prefer workflow-agent and supervisor-worker patterns over peer collaboration.

Passing the whole conversation to the sub-agent

It is convenient, it is expensive, and it frequently means sending a sub-agent data it has no authorisation to see. Pass what the contract requires and nothing more. This is a cost problem and a security problem, and it is invisible until someone audits it — which happens in Task 3.

Gating on confidence instead of irreversibility

A 0.97-confidence reservation is still a reservation. Confidence is not a safety property. Gate the action that cannot be undone, regardless of how sure the model claims to be — and write the gated list down where it can be reviewed.

The lesson this build makes undeniable

Replacing two agents with deterministic code raises end-to-end reliability more than any prompt change will.

Autonomy multiplies error. The reliability of an eight-step chain is the product of eight per-step rates, so every step you convert from a probabilistic model call to a plain function is a step that cannot fail — and the gain compounds through the whole chain. Nothing today is about making agents more autonomous.

Defend your result

“Our weakest step ran at 86%, which predicted 49% end to end; we observed 46%. Converting parts lookup and report formatting to code moved end-to-end success from 46% to 60%, cost from €0.24 to €0.16, and p95 latency from 14.2 s to 9.1 s. Our gate fires on irreversibility, and an outside approver used it in 18 seconds.”
